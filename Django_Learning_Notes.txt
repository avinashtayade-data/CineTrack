# Django Notes — Day 1

## Project: CineTrack — Personal Movie Library

### 1. What is Django?

Django is a high-level Python web framework used to build web applications quickly and efficiently.

It provides built-in features such as:

* URL routing
* Views
* Templates
* Models
* Database integration
* Authentication
* An administration panel

**Interview question: What is Django?**

**Answer:** Django is a high-level Python web framework that follows the Model-Template-View (MTV) architectural pattern. It helps developers build secure and maintainable web applications.

---

### 2. What is a Django project?

A Django project is the complete web application configuration. It contains settings and URL configuration and can include multiple apps.

Example:

```text
CineTrack/
├── manage.py
└── CineTrack/
    ├── settings.py
    ├── urls.py
    ├── asgi.py
    └── wsgi.py
```

Important files:

| File          | Purpose                            |
| ------------- | ---------------------------------- |
| `manage.py`   | Runs Django management commands    |
| `settings.py` | Contains project configuration     |
| `urls.py`     | Defines the project's URL patterns |
| `asgi.py`     | ASGI application entry point       |
| `wsgi.py`     | WSGI application entry point       |

**Interview question: What is the purpose of `manage.py`?**

**Answer:** `manage.py` is a command-line utility used to perform Django management tasks, such as running the development server, creating apps, and applying database migrations.

---

### 3. What is a Django app?

A Django app is a component of a project that handles a particular feature or area of functionality.

In CineTrack:

* Project: `CineTrack`
* App: `movies`
* Purpose: Manage movie-related features.

One Django project can contain multiple apps.

Example:

```text
CineTrack/
├── movies/
├── accounts/
└── reviews/
```

**Interview question: What is the difference between a project and an app?**

**Answer:** A project contains the overall configuration of a Django website, while an app handles a particular feature. A project can contain multiple apps.

---

### 4. What is `INSTALLED_APPS`?

`INSTALLED_APPS` is a setting in `settings.py` that lists the Django apps enabled in the project.

Example:

```python
INSTALLED_APPS = [
    'django.contrib.admin',
    'django.contrib.auth',
    'django.contrib.contenttypes',
    'django.contrib.sessions',
    'django.contrib.messages',
    'django.contrib.staticfiles',
    'movies',
]
```

We added `'movies'` so Django recognizes our app.

**Interview question: Why must we register an app in `INSTALLED_APPS`?**

**Answer:** Registering an app tells Django to include it in the project's app configuration. This allows Django to discover its models and perform other app-related operations.

A virtual environment is an isolated Python environment that keeps project dependencies separate from other Python projects.

When activated, the terminal displays:

### 6. What is `views.py`?

A view is Python code that receives a request, performs the necessary processing, and returns a response.

Our first view:

```python
from django.shortcuts import render

def home(request):
    return render(request, 'movies/home.html')
```

Explanation:

* `def home(request)`: Defines the view function.
* `request`: Contains information about the incoming HTTP request.
* `render()`: Renders a template and returns an HTTP response.
* `'movies/home.html'`: Identifies the template to render.

**Interview question: What is a view in Django?**

**Answer:** A view is a Python function or class that handles a web request and returns an HTTP response.

**Important:** `render()` does not directly display the webpage on the user's screen. It generates the response, and the browser displays the returned HTML.

---

### 7. What is URL routing?

URL routing determines which view should handle a particular URL.

Django uses `urls.py` to define URL patterns.

We created a separate `movies/urls.py` file:

```python
from django.urls import path
from . import views

urlpatterns = [
    path('', views.home, name='home'),
]
```

Explanation:

* `path()` defines a URL pattern.
* `''` represents the empty path relative to this URL configuration.
* `views.home` identifies the view to call.
* `name='home'` gives the URL pattern a name.

**Interview question: Why use a separate `urls.py` inside an app?**

**Answer:** It keeps URL patterns organized by app and makes the project easier to maintain.

---

### 8. What does `include()` do?

In the project's `CineTrack/urls.py`, we wrote:

```python
from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path('admin/', admin.site.urls),
    path('', include('movies.urls')),
]
```

The statement:

```python
path('', include('movies.urls'))
```

tells Django to check the URL patterns defined in `movies.urls` for matching paths.

The empty prefix means the app's URL patterns are available from the site's root.

**Interview question: Does `include()` redirect the browser?**

**Answer:** No. `include()` connects URL configurations. It does not redirect the browser to another URL.

A redirect sends the browser to another URL, whereas `include()` delegates URL matching to another URL configuration.

### 10. What is a Django model?

A model is a Python class that defines the structure of data managed through Django's ORM.

Our CineTrack model:

```python
from django.db import models

class Movie(models.Model):
    title = models.CharField(max_length=100)
    genre = models.CharField(max_length=50)
    release_year = models.IntegerField()
    description = models.TextField()
    rating = models.FloatField()

    def __str__(self):
        return self.title
```

Explanation:

* `class Movie(models.Model)`: Defines a Django model.
* `title`: Stores the movie title.
* `genre`: Stores the movie genre.
* `release_year`: Stores the release year.
* `description`: Stores a longer description.
* `rating`: Stores a decimal-valued rating.
* `__str__()`: Returns a readable string representation of the movie.

Field types:

| Field          | Purpose                       |
| -------------- | ----------------------------- |
| `CharField`    | Stores short text             |
| `IntegerField` | Stores whole numbers          |
| `TextField`    | Stores longer text            |
| `FloatField`   | Stores floating-point numbers |

**Interview question: Why do we inherit from `models.Model`?**

**Answer:** Inheriting from `models.Model` makes our class a Django model, allowing Django to use it for database operations through the ORM.

### 11. What is `__str__()`?

`__str__()` is a special Python method that returns a human-readable string representation of an object.

Example:

```python
def __str__(self):
    return self.title
```

If the movie title is `Inception`, the object is represented as:

```text
Inception
```

This makes objects easier to identify when inspecting them.

**Interview question: Is `__str__()` mandatory in every Django model?**

**Answer:** No. It is not mandatory, but it is recommended because it makes model objects easier to identify and understand.

### 12. What is a database migration?

A migration is a file containing instructions that describe changes to the database schema.

When we created the `Movie` model, we used two commands.

**Command 1:**

```powershell
python manage.py makemigrations
```

This creates migration files based on detected model changes.

**Command 2:**

```powershell
python manage.py migrate
```

This applies pending migrations to the database.

The terminal displayed:

```text
Applying movies.0001_initial... OK
```

This confirms that Django successfully applied the initial migration for our movies app.

**Interview question: What is the difference between `makemigrations` and `migrate`?**

**Answer:**

* `makemigrations` creates migration files describing model changes.
* `migrate` applies those migration instructions to the database.

Remember: creating a model class does not, by itself, create its database table. You must apply the relevant migration.

### 13. What is Django ORM?

ORM stands for **Object-Relational Mapper**.

Django's ORM lets us interact with database records using Python objects and methods rather than writing SQL for every operation.

Examples we will use in CineTrack:

```python
Movie.objects.create(...)
```

Creates a movie record.

```python
Movie.objects.all()
```

Retrieves all movie records.

```python
movie.title
```

Accesses the title field of a movie object.

**Interview question: What is the benefit of Django ORM?**

**Answer:** Django ORM allows developers to perform common database operations using Python code, reducing the need to write raw SQL queries manually.

### 14. Understanding the Django request flow

This is one of the most important concepts to remember.

For the CineTrack homepage, the flow is:

1. The user opens the homepage in a browser.
2. Django checks `CineTrack/urls.py`.
3. `include('movies.urls')` delegates URL matching to `movies/urls.py`.
4. Django matches the URL to `views.home`.
5. The view calls `render()`.
6. Django loads `movies/home.html` and renders it.
7. Django returns an HTTP response.
8. The browser displays the HTML.

Diagram:

Browser → Project URLs → App URLs → View → Template → HTTP response → Browser

**Interview question: Explain the request-response cycle in Django.**

**Answer:** When a request arrives, Django matches the URL to a view. The view processes the request and may interact with models or render a template. It returns an HTTP response, which Django sends back to the browser.

During our earlier Django practice, the terminal displayed:


HTTP status code `200` means the request was successful.

A `500` status code indicates an internal server error.

**Interview question: What does HTTP 200 mean?**

**Answer:** HTTP 200 OK indicates that the request succeeded.

### 16. Common beginner errors

#### A. IndentationError

Example:

```python
class Movie(models.Model):
title = models.CharField(max_length=100)
```

The field is not indented inside the class.

Correct:

```python
class Movie(models.Model):
    title = models.CharField(max_length=100)
```

Python indentation determines which statements belong inside classes and functions.

#### B. TemplateDoesNotExist

This happens when Django cannot find the requested template.

For example, the view should use:

```python
return render(request, 'movies/home.html')
```

When the template is stored at:

```text
movies/templates/movies/home.html
```

Do not include `templates/` in the template name when using Django's normal app template discovery.

#### C. Forgetting to register an app

If the app needs Django's app configuration and model discovery, make sure it is included in `INSTALLED_APPS`.

#### D. Forgetting migrations

After changing a model, run:

```powershell
python manage.py makemigrations
python manage.py migrate
```

Only run these commands when needed; you do not have to recreate migrations every time you change an HTML template.

## 3. Django Models

A **model** defines the structure of data stored in the database.

Our model is written in `movies/models.py`.

```python
from django.db import models

class Movie(models.Model):
    title = models.CharField(max_length=100)

    description = models.TextField()
```

### Understanding the code

**`class Movie(models.Model):`**

Stores short text, with a maximum length of 100 characters.

**`genre = models.CharField(max_length=50)`**

Stores the movie's genre.

**`release_year = models.IntegerField()`**

Stores an integer, such as `2010`.

**`description = models.TextField()`**

Stores longer text.

**`rating = models.FloatField()`**

Stores a floating-point number, such as `8.8`.

**`def __str__(self):`**

Controls the human-readable string representation of a movie object. Here, it returns the movie's title.

## 6. Django Views

A view receives a request and returns a response.

Our views are written in `movies/views.py`.

```python
from django.shortcuts import render, get_object_or_404
from .models import Movie

def home(request):
    movies = Movie.objects.all()
    return render(request, 'movies/home.html', {'movies': movies})

def movie_detail(request, movie_id):
    movie = get_object_or_404(Movie, id=movie_id)
    return render(request, 'movies/movie_detail.html', {'movie': movie})
```

### View 1: `home()`

```python
def home(request):
    movies = Movie.objects.all()
    return render(request, 'movies/home.html', {'movies': movies})
```

**Step 1:**

```python
movies = Movie.objects.all()
```

Retrieves all movie records from the database.

**Step 2:**

```python
return render(request, 'movies/home.html', {'movies': movies})
```

Renders the homepage template and passes the movie records to it.

The template can access these records using the variable `movies`.

### View 2: `movie_detail()`

```python
def movie_detail(request, movie_id):
    movie = get_object_or_404(Movie, id=movie_id)
    return render(request, 'movies/movie_detail.html', {'movie': movie})
```

**Step 1:**

```python
movie_id
```

Receives the movie ID captured from the URL.

**Step 2:**

```python
get_object_or_404(Movie, id=movie_id)
```

Retrieves the movie with that ID. If the movie does not exist, Django returns a 404 Not Found response.

**Step 3:**

```python
return render(request, 'movies/movie_detail.html', {'movie': movie})
```

Passes the selected movie object to the detail-page template.

## 7. Django URLs

URLs determine which view should handle a request.

Our application URL configuration is in `movies/urls.py`.

```python
from django.urls import path
from . import views

urlpatterns = [
    path('', views.home, name='home'),
    path('<int:movie_id>/', views.movie_detail, name='movie_detail'),
]
```

### Understanding the URL patterns

**Homepage:**

```python
path('', views.home, name='home')
```

The empty path represents the application's root URL.

**Movie detail page:**

```python
path('<int:movie_id>/', views.movie_detail, name='movie_detail')
```

Here:

* `<int:movie_id>` captures an integer from the URL.
* `views.movie_detail` is the view Django calls.
* `name='movie_detail'` gives the URL pattern a name.

For example, if a movie has ID `5`, its detail URL is:

```text
/5/
```

This assumes the application URLs are included at the website's root.

### Important: Main URL configuration

The application's URL patterns must be connected to the project's main URL configuration in `CineTrack/urls.py`.

For example:

```python
from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path('admin/', admin.site.urls),
    path('', include('movies.urls')),
]
```

The line:

```python
path('', include('movies.urls'))
```

connects the movie application's URL patterns to the project.

## 8. Django Templates

Templates are HTML files that display information to users.

Our templates are stored inside:

```text
movies/templates/movies/
```

We created two templates:

* `home.html`
* `movie_detail.html`

### Template variables

Django uses double curly braces to display variable values.

```django
{{ movie.title }}
```

This displays the movie's title.

Other examples:

```django
{{ movie.genre }}
{{ movie.release_year }}
{{ movie.description }}
{{ movie.rating }}
```

### For loop

To display multiple movies on the homepage:

```django
{% for movie in movies %}
    <h3>{{ movie.title }}</h3>
    <p>{{ movie.genre }}</p>
{% endfor %}
```

The loop goes through the movie records passed by the view.

For every movie, Django displays its title and genre.

### Empty condition

```django
{% for movie in movies %}
    <h3>{{ movie.title }}</h3>
{% empty %}
    <p>No movies have been added yet.</p>
{% endfor %}
```

If there are no movies, Django displays the message inside `{% empty %}`.

### Important difference

* `{{ variable }}` displays a value.
* `{% ... %}` performs a template operation, such as a loop or condition.

## 9. Django URL Names and the URL Template Tag

We used a hyperlink to open each movie's detail page.

```django
<a href="{% url 'movie_detail' movie.id %}">View Details</a>
```

### Understanding it

**`{% url ... %}`**

Asks Django to generate a URL from a named URL pattern.

**`'movie_detail'`**

The name of the URL pattern.

**`movie.id`**

The ID of the movie whose link is being generated.

For example, if the movie ID is `5`, Django generates:

```text
/5/
```

With this URL pattern:

```python
path('movie/<int:movie_id>/', views.movie_detail, name='movie_detail')
```

Django instead generates:

```text
/movie/5/
```

The template tag is useful because the URL pattern can change without requiring you to hardcode the new path in the HTML.

## 10. How the CineTrack Project Works

Suppose a user opens the homepage.

### Step 1: URL

The user visits:

```text
http://127.0.0.1:8000/
```

Django checks the URL configuration.

### Step 2: View

Django calls:

```python
home(request)
```

### Step 3: Model

The view runs:

```python
Movie.objects.all()
```

Django retrieves the movie records from the database.

### Step 4: Template

The view passes the records to:

```text
movies/home.html
```

### Step 5: Browser

Django renders the HTML, and the browser displays the movie library.

### Complete flow

```text
          User opens website
                  |
                  v
             URL pattern
                  |
                  v
                View
                  |
                  v
          Movie model / ORM
                  |
                  v
              Database
                  |
                  v
          View passes data
                  |
                  v
              Template
                  |
                  v
             HTML response
                  |
                  v
           Browser displays it
```

**Easy way to remember:**

* URL = Where should the request go?
* View = What should happen?
* Model = What data do we need?
* Template = How should the data be displayed?
